# 驯兽 ACR 设计说明

## 目标

驯兽 ACR（`驯兽ACR`）负责在玩家明确开启自动输出后，围绕当前手动选择的目标执行基础连击和捕获流程，并为高级技能提供可控的资源判断与开关。

设计原则：

- 默认不自动输出。
- 默认不自动使用高级技能。
- 只对玩家当前手动选择的目标执行动作。
- 捕获状态必须校验 `StatusId` 和 `SourceId`。
- 量谱和运行时状态读取只读，不写入游戏内存。
- 任何关键状态无法确认时，停止高级技能动作并显示原因。
- 推荐组合仅作为静态攻略展示，不接入自动输出决策、自动切笛或自动切换魔兽。

## 推荐组合

插件主窗口提供独立的“推荐组合”栏目，当前只展示静态攻略内容。

### 虫队：1、2 层速刷

推荐阵容：螳螂、胡蜂、库西。

1 笛召唤螳螂，施加物理易伤并使用释放技能，再使用最后一击；2 笛召唤胡蜂，使用释放技能进行自爆；3 笛召唤库西，使用释放技能后正常输出。整个流程的主要难点是螳螂的物理易伤不能空放。

### 水队：参考阵容

推荐阵容：蝾螈、巨型陆蟹、壳蟹。

蝾螈和巨型陆蟹分别负责魔法易伤与水属性易伤，壳蟹作为三号位主力输出。开战前先切换三号兽笛准备壳蟹的借用。1 笛召唤蝾螈，施加魔法易伤（释放），再使用最后一击；2 笛召唤巨型陆蟹，施加水属性易伤（释放），打一套连携之后使用最后一击；3 笛召唤壳蟹，正常输出。这里的“释放”指魔兽的释放技能。借用的水栖波用于远程止损，尽量安排在易伤 Buff 期间，也可以用于驱散敌方增益 Buff。

### 水队：1、2 层速刷变体

推荐阵容：蝾螈、巨型陆蟹、碧企鹅。

三号位使用高魔法伤害的碧企鹅。开战前先切换三号兽笛准备碧企鹅的借用。1 笛召唤蝾螈，施加魔法易伤（释放），再使用最后一击；2 笛召唤巨型陆蟹，施加水属性易伤（释放），无需等待完整连携，直接使用最后一击；3 笛召唤碧企鹅，正常输出。这里的“释放”指魔兽的释放技能。

参考视频：夜风，Bilibili 视频 BV1c1Y46AEnN，链接由推荐组合页面按钮打开。

投稿来源：网友“大三元”。

### 虫队：高1层速刷

推荐阵容：螳螂、蜂鸟、胡蜂。

- 1 笛召唤螳螂，施加物理易伤（释放），再使用最后一击。
- 2 笛召唤蜂鸟，使用释放“六连踹”（单体），再使用最后一击。
- 3 笛召唤胡蜂，等到 BOSS 血量低于 `25%` 时使用释放。

## 当前已实现

### 斗兽塔导航

工具列表提供“前往斗兽塔”栏目，点击“开始导航”后复用现有飞行导航和跨区传送流程，目标为 `TerritoryType=148`、`Map.RowId=4`、黑衣森林中央林区世界坐标 `X=24.238, Y=-6.003, Z=65.809`。

自动输出栏目提供默认关闭的“悬浮窗三列模式”开关。开启后悬浮窗高级技能按钮按三列排列：第一行御兽协作、兽灵协作、鼓劲；第二行万象·物理、万象·魔法、声援；第三行自动兽笛、最后一击、释放；第四行持续吸引、持续挑衅、安全盾牌。关闭时使用双列布局。

### 主动攻击

自动输出提供独立的“主动攻击”开关，悬浮窗标题栏显示可点击的“主动”标签：绿色表示开启，灰色表示关闭。

主动攻击关闭且玩家尚未进入战斗时，普通 ACR 不使用捕获、基础连击或高级目标技能；进入战斗后恢复正常决策。自动兽笛等无目标战前准备动作仍可运行。技能序列不受主动攻击开关限制；规则模式只在战斗中运行。两者仍要求自动输出总开关开启且未暂停。

旧配置升级时主动攻击默认开启，以保留既有行为；新配置默认关闭，避免选中目标后意外开怪。

### 基础自动输出

基础技能顺序：

```text
碎击斩 → 碎咬斧 → 裂盾劈
```

基础自动输出使用客户端稳定 RowId 判断和请求动作，不通过本地化技能名称解析：

| 用途 | RowId |
| --- | ---: |
| 碎击斩 | `44879` |
| 碎咬斧 | `44883` |
| 裂盾劈 | `44885` |
| 捕获 | `44880` |
| 捕获状态 | `4626` |

技能名称仅用于 UI 显示。客户端语言切换到国际服英文等环境时，不应依赖中文 Action 或 Status 名称作为运行时键。

执行前检查：

- 自动输出已开启。
- 玩家为驯兽师。
- 玩家存在、存活且没有读条。
- 不在切图、骑乘或剧情占用状态。
- 角色 HP 从 `0` 恢复为大于 `0` 后进入 3 秒复活保护，期间技能序列、规则模式、自动兽笛和普通 ACR 均不执行任何动作。
- 当前目标是可选中的 BattleNpc。
- 目标存在、存活且 HP 大于 0。
- `ActionManager` 可用且允许使用目标技能。

### 捕获流程

捕获标签有三种状态，悬浮窗标题栏点击标签按以下顺序循环：

```text
灰色“捕获”（尝试捕获和强制捕获均关闭）
→ 绿色“捕获”（尝试捕获开启）
→ 红色“捕获”（强制捕获开启）
→ 灰色“捕获”
```

绿色捕获状态下：

```text
目标血量 <= 捕获阈值
且目标没有自身施加的捕获状态
→ 选择捕获
```

目标血量高于阈值时继续基础连击。捕获阈值范围为 `1%~100%`，默认 `80%`，可在主页面和悬浮窗修改。

基础连击碎击斩 `44879`、碎咬斧 `44883`、裂盾劈 `44885` 的玩家到目标距离门禁统一按 `6 yalms` 判断；距离使用施法者中心到目标碰撞箱边缘，避免大型目标或中心距离约 `6.06` 时误判超距。超过该距离时不向动作系统发送请求，避免角色反复转向目标。其他玩家目标技能优先使用 `ActionManager.GetActionRange`，无法取得时回退 Action 表 `Range`；召唤兽释放距离同样扣除目标碰撞半径。

红色捕获状态为强制捕获：忽略目标已有捕获 Buff，但仍受目标血量阈值限制；同时受捕获请求后的等待窗口保护，不会在结果确认前重复请求。自动输出栏目提供“强制捕获”复选框；开启该选项会同步开启尝试捕获，关闭尝试捕获会同步关闭强制捕获。

捕获状态来源：

```text
status.StatusId == 捕获状态
且 status.SourceId == LocalPlayer.EntityId
→ 自身捕获状态
```

他人施加的同名状态不会阻止自身捕获判断。

捕获请求发送后进入短暂等待窗口，等待自身 `SourceId` 状态刷新；等待期间不会重复请求捕获，也不会继续对目标造成伤害。目标切换、目标失效或自动输出关闭时重置捕获状态。

“角色状态”拦截原因会拆分显示为技能节流等待、正在切图或传送、当前处于骑乘状态、剧情或特殊事件占用、角色已死亡、角色正在读条，避免国际服反馈时只能看到笼统的不可执行原因。

### 量谱读取

从以下地址只读采样 48 字节：

```text
JobGaugeManager.Instance()->CurrentGauge
```

字段：

| 字段 | 偏移 | 上限/拆分 |
| --- | --- | --- |
| 技力 | `+0x10` | `250` |
| 兽力 | `+0x11` | `250` |
| 当前兽笛 | `+0x13` | `1~3` 为对应兽笛 |
| 御兽之心 | `+0x18` | `raw >> 2` |
| 兽灵之心 | `+0x18` | `raw & 3` |

采样周期为 100ms，UI 使用缓存快照。

## 魔兽资料模型

图鉴编号与召唤物 DataId 的关系：

```text
DataId = 18915 + 图鉴编号
```

每个图鉴条目提供统一技能资料：

```text
BeastmasterSkillProfile
├── 图鉴编号
├── 魔兽名称
├── SummonDataId
├── 属性：猛 / 坚 / 魔 / 翔
├── 大招 ActionId
└── 释放 ActionId
```

注意：图鉴中的“大招 ActionId”是当前魔兽对应的宠物技能资料，用于识别属性；玩家实际释放驯兽师职业大招使用固定的 ActionId `47093`。

属性由大招 IconId 映射：

```text
3906 → 猛
3907 → 坚
3908 → 魔
3909 → 翔
```

## 高级技能开关

悬浮窗和主窗口都提供：

```text
御兽协作（黄豆）
兽灵协作（蓝豆）
万象流转（物理）
万象流转（魔法）
自动兽笛
自动最后一击
释放
```

开关关系：

```text
御兽协作（黄豆）和兽灵协作（蓝豆）互斥
→ 同时开启时自动关闭另一项

万象流转（物理）和万象流转（魔法）互斥
→ 同时开启时自动关闭另一项

释放关闭时，不自动请求当前召唤兽的 `ReleaseActionId`；手动协作流程仍由对应的黄豆/蓝豆选项控制。
```

高级技能支持以下调用路径：

- 手动大招按钮：通过悬浮窗主动请求固定职业大招 `47093`。
- 自动协作：在对应协作模式、当前魔兽和资源条件均满足时，按模式接入自动技能选择；大招由协作流程自动包含。
- 魔兽释放技能：“释放”开关开启后，以基础 ActionId `44890` 调用 `GetAdjustedActionId` 获取请求用 ActionId；射程从当前召唤兽图鉴条目的 `ReleaseActionId` 对应 Action 行读取，优先使用 `Range`，为 `0` 时使用 `EffectRange`。以召唤兽位置到目标碰撞箱边缘计算距离；存在有效射程且召唤兽未进入距离时不调用 `UseAction`，`Range` 与 `EffectRange` 均为 `0` 时跳过显式距离门禁并交给 `GetActionStatus` 判断。普通 ACR、规则模式和技能序列中的玩家目标技能也会检查玩家到目标的距离。释放与御兽之心/黄豆不是同一套状态，不能用黄豆变化确认释放完成。
- 释放保留总开关，并为一号、二号、三号兽笛分别提供独立开关和目标血量阈值。三笛默认开启、默认 `100%`，旧配置迁移后保持原有“目标满血也可释放”行为。只有当前笛开关开启且目标当前 HP 百分比小于等于对应阈值时才进入释放可用性和召唤兽射程判断；`100%` 包含满血目标。三笛阈值输入框按当前字体、内边距及两个步进按钮动态计算宽度；当前行空间不足时自动换行，避免高 DPI/UI 缩放下数值区被按钮挤压。
- 释放提供默认关闭的“只打BOSS”开关。开启后，目标最大 HP 必须严格大于玩家最大 HP 的 `5` 倍才允许释放；正好 `5` 倍不判定为 BOSS。通过 BOSS 判定后仍需满足当前笛独立开关、目标血量阈值、技能可用和召唤兽射程条件。
- “自动输出诊断”采用单一总开关，不提供模块筛选或发呆报警。开启后由插件内部记录全部普通 ACR 模块的状态边沿、技能成功请求和失败原因，不持续向聊天框输出汇总。相同技能和原因类别不会因轮询、距离数值或资源数值变化重复记录；可用性、状态码类别或技能发生变化时记录新边沿。
- 自动输出诊断折叠栏提供战斗日志下拉选择、复制和清空。进入战斗时开始记录，离开战斗时归档；内存中保留最近 10 场，每场最多 500 条，插件重载后清空。日志用于事后分析发呆原因，不读取聊天框。
- 兽笛循环连招已保留实现但当前暂时禁用，未接入自动决策入口。恢复时的设计顺序为：一号兽笛（`44881`，要求未进入战斗）→ 释放（基础 `44890`，运行时调整）→ 最后一击（`44891`）→ 二号兽笛（`44892`）→ 释放 → 最后一击 → 三号兽笛（`44894`）→ 释放。
 - 该循环完成后自动关闭，并等待一号兽笛冷却完成后才允许再次启动；关闭开关或自动输出时应清空阶段和冷却等待状态。

三式提供“物理”和“魔法”两个互斥模式。任一模式开启后，只有玩家自身状态列表已经存在生息或死灭状态，并且御兽之心达到 3 层时，才使用无目标技能鼓劲 `44905`；缺少任一条件都不会释放鼓劲。黑白状态不校验 `SourceId`，与参考 DLL 的 `HasStatus` 判断一致。鼓劲消耗黄豆后，按客户端实测映射选择终结技能；该映射与参考 DLL 的反编译结果相反：

| 状态 | 万象流转（物理） | 万象流转（魔法） |
| --- | --- | --- |
| 生息（白，`4599`） | 利鹰坚爪 `44931` | 灾祸天翔 `44933` |
| 死灭（黑/紫，`4600`） | 狂猛怒火 `44930` | 升魔暴落 `44932` |

鼓劲优先于三式终结技能；所有三式动作仅在 `GetActionStatus == 0` 时请求。三式第二段需要有效的当前敌对目标。

自动兽笛开启后，只在当前没有召唤魔兽时运行。程序按一号 `44881`、二号 `44892`、三号 `44894` 的顺序检查，并使用第一个 `GetActionStatus == 0` 的兽笛。请求成功后进入 1 秒召唤确认窗口，每 100ms 检查当前兽笛量谱或己方召唤物；确认窗口结束前不会检查或使用下一支兽笛，避免客户端召唤延迟导致连续使用兽笛 1 和兽笛 2。关闭自动兽笛、暂停或关闭自动输出时清理等待状态。

鼓劲 `44905` 和声援 `44904` 为独立高级技能开关，默认关闭。鼓劲在御兽之心为 `0` 时释放，或在御兽之心为 `3` 且技力为 `0` 时也释放；声援在兽灵之心为 `0` 时释放，或在兽灵之心为 `3` 且兽力为 `0` 时也释放。两者均为无目标能力技，在 GCD 转圈期间穿插，状态不可用或请求失败时回退其他输出。借用 `44895` 和魔兽技 `44886` 为独立开关，默认关闭；开启后按借用→魔兽技顺序参与能力技穿插。

安全盾牌使用盾牌冲击 `44893`，默认关闭。玩家到当前目标碰撞箱边缘的距离不超过 `3 yalms` 且动作状态可用时才发送请求；成功请求后进入独立 `2s` 冷却，期间即使动作状态再次变为可用也不会连续发送。请求失败不启动冷却；关闭、暂停自动输出或角色复活时清空该冷却。

悬浮窗高级技能使用按钮开关。双列模式依次为协作、万象流转、鼓劲/声援、自动兽笛/待定、释放/最后一击、持续吸引/持续挑衅；三列模式按四行三列排列。持续吸引与持续挑衅按钮直接切换规则模式内对应的内置斗兽塔规则，开启时使用淡黄色背景；规则绑定使用 ActionId 与状态 ID，不依赖可编辑名称。
自动输出栏目显示完整接管优先级：技能序列 → 低血量恢复药 → 规则模式 → 动画锁 → 协作二段 → GCD 判断（万象流转 → 协作一段 → 基础连击）→ GCD 转圈时能力技穿插（捕获 → 借用 → 魔兽技 → 鼓劲 → 声援 → 释放 → 最后一击 → 安全盾牌 → 大招，每窗口最多 2 个）。悬浮窗不显示该说明。

### 奇弈恢复药

“低血量自动使用恢复药”默认关闭，血量阈值默认 `30%`，可配置范围为 `1%~100%`。仅当自动输出开启且未暂停、玩家为驯兽师、位于斗兽塔 TerritoryType `1339~1343`、已经进入战斗、玩家存活且自身血量严格小于阈值时运行；血量正好等于阈值时不触发。

恢复类内部 XBMItem ID 为：1~4级恢复药 `76~79`、1~3级魔兽药粉 `80~82`、吸血鬼之牙 `134`、魔兽吸血药 `135`、魔兽恢复药套装 `140`。选择优先级固定为 `套装 → 4级 → 3级 → 2级 → 1级恢复药 → 3级 → 2级 → 1级药粉 → 吸血药 → 吸血鬼之牙`，不依赖道具栏显示顺序；吸血药和吸血鬼之牙仅作为其他恢复道具均不可用时的后备项，吸血鬼之牙要求有效敌对目标。任一恢复类道具成功使用后共享 `2s` 使用间隔。已在客户端将阈值设置为 `60%`，确认自身血量低于阈值时成功使用3级魔兽恢复药。

奇弈恢复药不属于普通背包物品，不能通过 `ActionManager.UseAction(ActionType.Item)` 执行。运行时使用以下路径：

1. 从 `AgentId 497` 的 `agent + 0x50 + displaySlot * 8` 读取十个显示槽位到内部库存槽位的映射。
2. 使用 `InstanceContentDirector + 0x2384 + inventorySlot * 12` 的 ItemId 二次校验映射，且要求 `InstanceContentType == 22`。
3. 通过签名扫描取得原生可用状态函数和 Agent 映射刷新函数；任一签名失效时停用自动恢复药并记录警告，不盲目执行槽位。映射仅在 `director`、`TerritoryType` 或库存槽位 ItemId 变化时刷新。
4. 使用恢复药对应 ActionId `46959~46961` 验证能否对玩家自身使用及距离/视线状态。
5. 遍历 `RaptureHotbarModule` 的 0~17 号热键栏、每个热键栏 0~15 槽位，找到 `CommandType == 36` 且 `CommandId == displaySlot` 的真实槽位；临时将 `TargetSystem.SoftTarget` 设为请求目标，再调用 `RaptureHotbarModule.ExecuteSlotById(hotbarId, slotId)` 执行，最后恢复原软目标。恢复类道具使用玩家自身，各种牙和吸血鬼之牙使用有效敌对目标；不使用 `ExecuteSlot` 传入临时构造的 `HotbarSlot`。

道具请求先进入最长 `2s` 的共享待执行队列，并在后续 Framework 更新中重新校验槽位、区域、目标、原生状态和动画锁。动画锁存在时保留请求等待；真正调用 `ExecuteSlotById` 后，恢复类道具设置 `2s` 防重复窗口。技能序列保持最高优先级；恢复药请求入队后本轮不再执行规则或普通 ACR。

> 客户端更新后，`RaptureHotbarModule.ExecuteSlot` 传入临时构造的 `HotbarSlot`（`CommandType=(HotbarSlotType)36`、`CommandId=displaySlot`）已不再生效，且 `ActionManager.UseAction(ActionType.Action, 46959~46980)` 只产生动画锁而不使用道具。实测确认改用游戏真实热键栏槽位 `ExecuteSlotById` 可正常消耗道具，故恢复类与规则类奇弈道具统一走该路径。

最后一击按当前 `1/2/3` 号兽笛分别提供独立开关和 `1%~100%` 的宝宝血量阈值，默认 `20%`。插件从己方召唤物读取当前/最大 HP；当最后一击总开关开启、当前兽笛对应开关开启、宝宝仍存活且血量小于等于该笛阈值、当前敌对目标有效，并且最后一击 `44891` 的 `GetActionStatus == 0` 时，对当前敌对目标请求该技能；`100%` 阈值包含满血宝宝。技能不可用时回退其他输出，不阻塞基础连击。悬浮窗只保留一个最后一击功能总开关，不修改三笛独立设置；各笛位开关和阈值仅在自动输出栏目的高级技能中设置。最后一击三笛阈值输入框与释放设置共用缩放自适应布局：正常宽度下与开关同排，剩余空间不足时自动换行，保证 `100%` 数值区和 `- / +` 步进按钮均完整显示。

“最后一击 · 等待释放”开启后，只有当前召唤兽的调整后释放技能不可用时，才允许使用最后一击。释放技能状态可用但召唤兽尚未进入释放距离时，仍继续等待释放，不能绕过距离条件使用最后一击。该判断不依赖“释放”自动开关，释放可以由自动逻辑或手动操作完成；切换兽笛、召唤兽变化或消失时重新判断当前释放状态。

最后一击等待释放还会检查当前笛的释放独立开关和目标血量阈值：当前笛释放关闭或目标血量高于阈值时，不计划自动释放，因此最后一击不等待；满足释放条件且释放仍可用时才继续等待。

最后一击 `44891` 成功请求后启动全局 `5s` 保护窗口。窗口内禁止请求大招 `47093`、闪崩斧 `44884`、寒风斧 `44887`、回旋斧 `44888` 和风啸斧 `44889`。普通 ACR、协作两段、手动大招、规则模式和技能序列共用该保护；倒计时未结束时显示剩余时间并等待，不会绕过保护。

基础技能（1→2→3）有独立开关。关闭后仍保留捕获和已启用的高级技能，但不会自动使用碎击斩、碎咬斧和裂盾劈。

基础技能（1→2→3）与万象流转、协作同属 GCD 技能。普通 ACR 以基础连击当前步骤的 `GetActionStatus == 0` 判断 GCD 是否转好：转好时优先万象流转、协作，其次基础连击；GCD 转圈期间才穿插能力技，且每个 GCD 窗口最多 2 个能力技。该结构取代了旧的“新目标先请求一次基础 GCD”门槛，避免开战后连续使用能力技而基础连击没有启动。技能序列、规则模式和协作第二段仍保留更高优先级。

规则模式内置“斗兽塔技能”规则集，仅在 TerritoryType `1339~1343` 生效。默认包含两条关闭的维护规则和一条开启的最终爆发规则：

- 持续吸引（宝宝抗）：自身状态列表没有被保护 `2413` 时，使用无目标技能吸引注意 `46751`。
- 持续挑衅（自己抗）：自身状态列表没有仇恨上升 `5586` 时，使用无目标技能挑衅 `46750`。
- 最终爆发-1层：当前目标 `BaseId == 19344` 时，使用“各种牙”奇弈道具。

三项同时满足时按规则顺序处理；持续吸引和持续挑衅默认关闭，最终爆发-1层默认开启。技能或奇弈道具不可用、状态非零或请求失败时发送诊断并回退其他输出，不阻塞技能序列、自动兽笛、捕获或基础连击。区域不在 `1339~1343` 时不执行这些规则。

规则条件支持：自身/目标 BUFF、DataID BUFF、DataID 读条、目标读条和目标 DATAID。目标 DATAID 条件只比较当前目标的 `BaseId`，不使用目标名称或本地化文本。

规则执行方式支持技能和奇弈道具。奇弈道具不在规则界面输入 ID，而是选择以下固定类型：

- 恢复药：按套装 `140` → 4/3/2/1级恢复药 `79/78/77/76` → 3/2/1级药粉 `82/81/80` → 吸血药 `135` → 吸血鬼之牙 `134` 优先级使用；仅吸血鬼之牙要求当前目标。
- 各种牙：从已确认的牙中自动选择当前存在且可用的道具，对当前目标使用。

目前已确认的牙 ID 为：火之牙 `128`、冰之牙 `129`、水之牙 `130`、雷之牙 `131`、土之牙 `132`、风之牙 `133`、吸血鬼之牙 `134`、星之沙 `139`。选择“各种牙”时按 `134 → 133 → 132 → 131 → 130 → 129 → 128 → 139` 顺序尝试；后续发现新 ID 只需补充内部候选列表，不改变规则配置格式。恢复药与各种牙均通过 Agent 497 显示槽位映射、InstanceContentDirector 库存校验和 `RaptureHotbarModule.ExecuteSlotById` 执行，并临时设置对应 SoftTarget。

奇弈道具 DEBUG 仅用于只读检查当前 `XBMContentsMainHUD` 数据，不触发回调、不使用道具、不写入内存。列表只接受 `76~143` 范围内的有效 ID，并按 ID 去重，过滤 UI 前置数据和 `243xxx` 等解析伪条目。

规则诊断由全局开关和规则集诊断级别共同控制。完整级别输出成功释放技能、成功使用奇弈道具和未命中状态；失败诊断按规则及稳定失败原因去重，相同原因不重复刷屏，原因变化或成功恢复后才重新输出。动态冷却剩余时间和动作锁剩余时间不参与失败原因比较。

区域范围使用 `ClientState.TerritoryType` 判断，包含首尾 `1339`、`1340`、`1341`、`1342`、`1343`。DEBUG 关键词查询提供“区域”类型：输入数字时按 `TerritoryType.RowId` 精确查询，输入文字时按区域名称模糊查询，并输出区域名、`Map.RowId` 和关联的 `ContentFinderCondition`。

悬浮窗标题栏的“自动/暂停”按钮可随时暂停或恢复自动输出；暂停是独立状态，不会关闭自动输出总开关。自动输出栏目也提供相同的暂停开关。暂停会清理捕获等待和协作待续状态，避免恢复后继续旧流程。

配置保存由 `BeastmasterConfiguration.Save` 捕获文件系统异常。Dalamud 无法写入 `pluginConfigs/Beastmaster.json` 时，插件每 5 秒最多记录一次错误且不再让异常冒泡中断 ImGui 绘制；该保护不替代目录写入权限，权限异常期间的设置仍无法持久化。

### 魔兽等级与经验

斗兽塔每轮结算的 `XBMResult` 提供 10 个参战宝宝的结算前后养成数据。已通过图鉴 2 松鼠种从 4 级 `61/100` 升至 6 级 `9/100` 的结算验证以下布局：

| 数据 | AtkValue 范围 | 映射 |
| --- | --- | --- |
| 图标 | `73..82` | 图鉴编号 = IconId - `242000` |
| 结算前经验 | `89..98` | 每格当前经验，满级为占位值 |
| 结算后经验 | `105..114` | 每格结算后经验 |
| 结算前等级 | `121..130` | 每格结算前兽级 |
| 结算后等级 | `137..146` | 每格结算后兽级 |

插件每 `250ms` 只读检查可见的 `XBMResult`，校验图标范围 `242001~242050`、等级 `1~25` 和经验 `0~99`。同一组结算后数据连续稳定至少 `500ms` 后，才按图鉴编号保存到当前角色进度，避免升级动画过程中的中间值和重复写入；结算页关闭后停止读取。该流程不触发结算回调、不自动退出页面，也不写入游戏内存。

插件图鉴将原静态“等级”列明确标为“捕获等级”，新增“兽级”和“经验”列。未从结算页同步过的宝宝显示 `--`；25 级宝宝经验显示 `--/--`。数据按角色隔离持久化，鼠标悬停经验可查看最近同步时间。目前结算页只会增量同步参战宝宝，首次全量同步仍需继续定位底层 50 项养成数据。

NPC 处打开原生 `XBMMonsterNotebook` 并选中宝宝时，还可从详情字段读取单只宝宝：`Value[229]` 为显示编号、`Value[231]` 为图标、`Value[258]` 为兽级、`Value[260]` 为经验文本、`Value[261]` 为当前经验、`Value[262]` 为经验上限。`Value[227]` 在切换宝宝时可能保持旧编号，不参与同步。插件要求显示编号与 `IconId - 242000` 一致，并等待完整快照连续稳定后才补充缓存。该路径不触发点击或翻页，不需要打开魔兽编队，但仍需要原生图鉴可见；完全不打开任何游戏窗口的 50 项全量刷新尚未实现。

图鉴排序将静态来源等级明确命名为“捕获等级”。“按捕获等级排序”和“按兽级排序”互斥；按兽级排序支持正序和逆序，尚未同步兽级的魔兽始终排在末尾。开启按地图排序时，先按当前地图和区域分组，再在组内应用所选等级排序。

图鉴页面提供紧凑刷新说明：斗兽结算自动同步参战魔兽；与 NPC 劳妲对话打开原生魔兽图鉴后，将鼠标停留在对应魔兽约 1 秒可同步单只数据；25 级经验显示 `--/--`。页面中“劳妲”和“原生魔兽图鉴”使用黄色强调，结算同步和满级提示使用红色关键词。

### 斗兽奇弈

插件提供独立“斗兽奇弈”栏目，内部横向排列“奇盘编队”“斗兽成就”“斗兽攻略”三个子页签。现有编队功能位于“奇盘编队”子页；斗兽成就和斗兽攻略先提供页面入口，后续补充资料。

奇盘编队提供游戏编队界面专用悬浮窗。预设不绑定具体盘或地图，只保存名称、栏位数量和有序图鉴编号列表。栏位数量支持 `10/12/14/15`，允许少于栏位容量，空位只能位于名单末尾，同一只魔兽不能重复。

预设编辑下拉仅显示已捕获魔兽，格式为“编号 - 名称 - 兽级”，内部只保存稳定图鉴编号。支持新建、复制、删除、重命名、分享和导入；分享格式为 `BSTPARTY|1`，只包含名称、栏位数和成员编号，不包含角色兽级缓存。导入后生成新 ID，并为重名预设追加唯一后缀。

`XBMPetParty` 读取结构：`Value[5]` 为当前成员数，`Value[1162]` 为当前栏位容量；成员从 `Value[6]` 开始、步长 `77`，块内 `+1` 为图标、`+3` 为名称、`+76` 为图鉴编号。插件要求图标等于 `242000 + 图鉴编号`，支持读取当前容量为 `10/12/14/15` 的编队。

应用预设时以游戏当前栏位容量为准。当前容量小于预设栏位时，只应用预设前当前容量个位置并提示；当前容量大于预设栏位时，应用预设成员并提示空余位置数量。操作依次使用已验证的 Agent 501 清空协议、文本匹配后的 `SelectYesno` 标准确认回调、图鉴原生翻页回调和 Agent 500 加入协议。图鉴 1~25 使用第一页页内索引，26~50 切换第二页后使用页内索引。每一步等待 `XBMPetParty` 快照确认，并在 5 秒超时或最终名单不一致时中止；失败后保留已形成的部分队伍，不自动恢复原队伍。

“应用编队”必须由用户点击，不会因打开编队界面自动执行。若原生图鉴已打开则直接复用，未打开时才由插件打开。顶部操作布局为第一行预设管理、分享/导入和应用按钮，第二行预设选择；原生操作诊断和单步测试已从用户界面隐藏。

大招调用会保留目标、职业、量谱、射程和 `ActionManager` 检查。所有普通 ACR 技能仅在 `GetActionStatus == 0` 时调用 `UseAction`，不再使用状态码非零时的请求兜底。

协作技按两段候选流程请求。第一段成功后保存第二段及预期的一式属性状态，并在 7 秒窗口内等待人物自身状态列表出现对应 Buff：翔 `4595`、猛 `4596`、坚 `4597`、魔 `4598`。检查不校验 `SourceId`；等待 Buff 期间保留第二段最高优先级但不重复开启第一段，允许普通 ACR 回退执行释放、捕获和基础连击，避免等待窗口造成发呆。Buff 出现后下一轮立即优先执行第二段，并记录等待、状态码、距离、请求失败和完成边沿。

- 御兽协作（黄豆）：大招作为第一段；召唤兽前摇可能延迟大招结算，出现当前魔兽属性对应的一式 Buff 后，才释放技力技第二段以获得黄豆。
- 兽灵协作（蓝豆）：属性技作为第一段；出现该属性技对应的一式 Buff 后，才释放大招第二段以获得蓝豆。

目标切换、暂停、关闭自动输出或等待超时会清除待续状态。

## 国际服兼容规则

- 自动输出、导航和图鉴排序优先使用稳定 ID：`Action.RowId`、`Status.RowId`、`TerritoryType.RowId`、`Map.RowId`、`ContentFinderCondition.RowId`。
- 中文名称保留为界面文案、资料展示和缺少稳定 ID 时的最后回退，不作为自动输出动作选择的唯一依据。
- 野外图鉴导航优先按 `Map.RowId + TerritoryType` 定位地图，其次按 `TerritoryType`，最后才按本地化地图名回退。
- DEBUG 的“自动输出状态”用于回传 `BetweenAreas`、`Mounted`、`OccupiedInCutSceneEvent`、`InCombat`、HP、读条和目标状态。
- 图鉴同步读取 `XBMMonsterNotebook` 的原生 `AtkValue`。编号数值、捕获 Bool 和图标 RowId 参与结构校验；`1`、`No.1` 等编号显示文本只用于诊断，不参与校验，避免客户端语言差异导致同步失败。
- 图鉴同步仍要求两页共 50 项、页码有效、两页捕获总数一致，并核对捕获 Bool 与图标 RowId；任一语言无关字段异常时停止同步，不覆盖角色原有进度。
- 图鉴同步失败时保留诊断文本，可通过“复制同步诊断”取得页码、`AtkValuesCount` 以及编号、捕获、图标和文本字段的原始类型和值，便于核对客户端版本差异。

客户端实测：三号笛为库西时，`借用 44895` 调整为 `47238`，`魔兽技 44886` 调整为 `百兽肤 44896`，`释放 44890` 调整为 `47092`。序列应请求调整后 ID，不直接写死这些运行时结果。

倒计时读取参考 AE3：从 `AgentId.CountDownSettingDialog` 对应 Agent 读取 `Timer @ 0x28`、`Active @ 0x38`、`Initiator @ 0x3C`。当前阶段只提供只读快照与 DEBUG 验证，不安装签名 Hook；读取会检查空指针、非有限数值以及 `0~3600` 秒范围。

倒计时由独立缓存服务轮询。自动输出关闭、暂停、未登录或职业不是驯兽师时不访问 Agent；满足前置条件后，待机状态每 `100ms` 采样一次，倒计时激活后每 `50ms` 采样一次。DEBUG 和后续技能序列执行器只读取缓存，不在 UI 绘制帧中直接访问 Agent。

### 自定义倒计时

除游戏原生倒计时外，支持通过 `/驯兽师 倒计时 [秒数]` 启动自定义倒计时。默认 `10` 秒，可指定 `1~3600` 秒。自定义倒计时与原生倒计时使用相同的 `BeastmasterCountdownTransition` 机制，技能序列服务无需区分倒计时来源。

前置条件：自动输出已开启、当前职业为驯兽师。自定义倒计时启动后立即设置 `LastTransition = Started`，序列服务检测到该边沿后进入 `Countdown` 状态。倒计时期间每 `50ms` 更新剩余时间，归零后设置 `LastTransition = Completed`，序列进入 `WaitingForCombat` 状态。

自动输出关闭、暂停、未登录或职业切换时自动取消自定义倒计时。使用 `/驯兽师 取消倒计时` 可手动取消。

实测取消倒计时后 `Active=False`、`Timer=0`、`Initiator=0`。缓存服务记录倒计时边沿：非激活到激活为开始；激活到非激活且上一采样剩余时间大于 `0.25s` 为取消；上一采样已接近零则为自然归零。最近边沿和时间保留在 DEBUG 中，避免必须在变化瞬间读取。

DEBUG“技能序列验证数据”输出原生倒计时状态、当前兽笛和召唤兽、目标、战斗状态，以及借用、魔兽技、释放、本能技能和盾牌冲击的基础/调整后 ActionId 与状态码。

技能序列栏目提供默认关闭的“序列诊断”开关。开启后仅在序列启动、技能请求成功、进入战斗、完成和中止时输出本地聊天信息；前缀格式为 `[驯兽师序列诊断 HH:mm:ss]`，失败重试轮询不输出，相同消息在 2 秒内去重。

当前提供可恢复的内置“虫队模版序列”，启用后仅从下一次团队倒计时开始执行，不追加入场中已经开始的倒计时：

```text
T-9  三号兽笛
T-5  借用
T-4  一号兽笛
T-2  魔兽技（必须调整为百兽肤）
T-0  盾牌冲击
进入战斗后：
碎击斩 → 鼓劲 → 释放
碎咬斧 → 声援 → 最后一击
裂盾劈 → 二号兽笛 → 释放
三号兽笛
```

序列运行时优先于规则模式、自动兽笛和普通 ACR。每一步按实际调整后的 ActionId 读取 `ClassJobLevel`，角色等级不足时直接跳过并继续序列，包括关键倒计时技能。序列中的释放步骤与普通 ACR 共用召唤兽到目标的距离门禁。倒计时取消、步骤超时、目标失效、切图、切换职业、角色死亡、自动输出关闭或暂停时中止；完成或中止后归还普通 ACR 控制。每个战斗步骤超时为 8 秒，盾牌冲击后等待进入战斗的窗口为 2 秒。

同时内置默认关闭的“测试序列”，流程为 `T-3 一号兽笛 → T-0 盾牌冲击 → 进入战斗后碎击斩`，用于验证倒计时、兽笛确认、目标技能和战斗阶段接续。

## 规则模式

规则模式是独立的规则配置栏目，采用“规则集 → 有序规则”结构。“规则诊断”全局开关位于“启用规则模式”下方并默认关闭；开启后再按各规则集的规则诊断级别决定输出失败或完整信息。规则集支持启用开关、`TerritoryType` 区域包含/排除；规则支持自身 BUFF、目标 BUFF、DataID BUFF、DataID 读条、目标读条、目标 DATAID、自身血量、目标血量和目标为 BOSS（IsBoss）检测。血量检测可选择大于或小于阈值，BUFF 条件可选择存在或缺失，技能使用稳定 `Action.RowId`。

规则模式仅在 `ConditionFlag.InCombat` 为真时检查和执行。规则集和规则均按界面顺序检查，越靠前优先级越高。DataID 检测遍历当前场景内存活的战斗 NPC，但规则技能始终对当前手动目标释放，不会自动切换目标。规则命中后若技能或道具不可用、距离不足或请求失败，会记录诊断并继续检查后续规则；只有某条规则成功执行才结束本轮。全部规则均未命中或无法执行后才回退普通 ACR。

规则集可使用带 `BSTRULESET|1` 版本头的文本导入导出；导入会新增规则集，不覆盖已有配置。每个规则集最多 100 条规则、100 个区域 ID。规则模式默认开启，内置斗兽塔规则集包含默认关闭的持续吸引与持续挑衅，配置版本为 19。

自身血量和目标血量检测均使用当前 HP / 最大 HP 计算百分比，并提供“大于 / 小于”条件选择，阈值范围为 `1%~100%`。大于采用严格 `>`，小于采用严格 `<`，等于阈值时均不命中；目标无效或最大 HP 为 `0` 时目标血量条件不命中。规则导出使用可选字段 `血量条件` 和 `血量阈值`；旧 `BSTRULESET|1` 文本未提供时使用“大于 50%”。配置 Version 40 增加目标血量检测。

每条规则支持最多 10 个检测条件，并可选择“全部满足（AND）”或“任意满足（OR）”。AND 要求所有条件同时命中，OR 在任一条件命中时执行；诊断原因会按“且 / 或”合并已命中的条件。执行方式和技能/奇弈道具仍属于整条规则。规则导出继续使用 `BSTRULESET|1`，新增 `条件关系` 和 `条件{序号}...` 字段；旧单条件文本导入时自动转换为一个条件。配置 Version 41 将现有规则迁移为条件列表。

“目标为 BOSS（IsBoss）”不依赖 DataID：当前手动目标最大 HP 严格大于玩家最大 HP 的 `5` 倍时命中，等于 `5` 倍时不命中；目标无效或任一最大 HP 为 `0` 时不命中。配置 Version 42 增加该检测类型。

奇弈道具执行类型包括恢复类道具、各种牙、吸血鬼之牙 `134`、闪躲之书 `137`、反射之书 `136`、时之沙 `138`、星之沙 `139` 和魔兽刚力药 `104`。各种牙按固定优先级 `吸血鬼之牙 134 → 风 133 → 土 132 → 雷 131 → 水 130 → 冰 129 → 火 128 → 星之沙 139` 选择第一个可用项，要求有效敌对目标；书、时之沙和刚力药固定对玩家自身使用。所有道具仍通过 Agent 497 槽位映射、InstanceContentDirector 库存校验和 `RaptureHotbarModule.ExecuteSlotById` 执行。

## 技能决策优先级

普通 ACR 采用「GCD 技能优先 + 能力技穿插」的结构，不再使用线性优先级列表。

### 技能分类

| 类型 | 技能 |
| --- | --- |
| GCD | 基础连击（碎击斩 `44879` → 碎咬斧 `44883` → 裂盾劈 `44885`）、万象流转（物理/魔法）、协作（御兽/兽灵） |
| 能力技（OGCD） | 释放、最后一击、鼓劲、声援、安全盾牌、兽笛 1/2/3、捕获、大招、借用、魔兽技 |

### 决策顺序

```text
自动输出总开关与暂停状态
→ 角色状态
→ 技能序列
→ 战斗中的规则模式
→ 低血量自动恢复药
→ 当前目标
→ 捕获等待保护
→ 动画锁检查（AnimationLock > 0 时等待）
→ 待续协作第二段
→ 无魔兽时自动兽笛
→ GCD 判断（基础连击当前步骤 GetActionStatus == 0）
   ├─ GCD 转好 → GCD 技能：万象流转 → 协作一段 → 基础连击（成功则重置能力技计数）
   └─ GCD 转圈 → 能力技穿插（每个 GCD 窗口最多 2 个，无动画锁时）：
        捕获 → 借用 → 魔兽技 → 鼓劲 → 声援 → 释放 → 最后一击 → 安全盾牌 → 大招
```

### 能力技穿插规则

- 能力技只在 GCD 转圈期间释放，且 `AnimationLock == 0` 时才请求。
- 每个 GCD 窗口最多释放 2 个能力技；GCD 技能成功后重置计数。
- 安全盾牌 `44893` 保留 2 秒独立冷却，3 层充能自然分散到连续 GCD 窗口。
- 借用 `44895` 与魔兽技 `44886` 有独立开关，默认关闭；开启后按能力技优先级参与自动输出。
- 大招 `47093` 仅在协作关闭时作为独立能力技自动释放，避免与协作第一段冲突。
- 自动兽笛在无魔兽时独立执行（不依赖 GCD 转圈），不受能力技穿插计数限制。

暂停时不执行任何动作，并清理捕获等待和协作待续状态。

### 暂存的兽笛循环连招

该功能目前不显示入口，也不会执行动作。代码中的阶段状态仅作为后续恢复设计记录：

```text
未战斗 + 一号兽笛可用
→ 一号兽笛
→ 释放
→ 最后一击
→ 二号兽笛
→ 释放
→ 最后一击
→ 三号兽笛
→ 释放
→ 关闭循环并等待一号兽笛冷却
```

约束：

- 一号兽笛阶段不要求当前目标。
- 释放和最后一击阶段要求有效 BattleNpc 目标。
- 任一动作不可用或请求失败时停留在当前阶段，不跳过动作。
- 循环未启用时不得因为残留阶段或冷却状态继续释放动作。
- 恢复入口前需要重新验证兽笛 ActionId、无目标调用方式和一号兽笛冷却状态码。

## 上线验证清单

验证时优先使用 DEBUG 页的“读取协力验证数据”按钮。该按钮只读输出量谱、当前魔兽、目标、关键 Action 状态码和自身属性状态。

### 验证步骤

1. 进入安全区域，切换驯兽师，不开自动输出，召唤任意魔兽。
2. 点击“读取协力验证数据”，记录初始技力、兽力、心数、兽笛、魔兽属性和自身属性状态。
3. 只使用普通技能，等待量谱变化，再点击一次按钮，确认 `+0x10` 和 `+0x11` 的变化方向。
4. 开启自动输出，但先关闭两个协力模式，确认基础连击不受影响。
5. 开启“御兽协作（黄豆）”，在技力、兽力达到要求后记录悬浮窗下一技能；确认是否先请求 `47093`。
6. 第一段技能完成后立即点击“读取协力验证数据”，记录自身属性状态、Action 状态码和量谱变化。
7. 在 7 秒内再次点击按钮，确认第二段属性斧所需状态和实际 Action 状态码。
8. 关闭黄豆，开启“兽灵协作（蓝豆）”，重复步骤 5~7，确认第一段是否为属性斧、第二段是否为 `47093`。
9. 分别测试两种模式同时开启，确认 UI 自动关闭其中一个，不能同时运行。
10. 测试切换目标、目标死亡、召唤兽消失和切换职业，确认待续段会被清除且不会对旧目标继续请求技能。

每个阶段至少回传：

- 悬浮窗截图或文字：下一技能、原因、捕获状态。
- “读取协力验证数据”的完整输出。
- 实际是否释放了第一段和第二段。
- 两段技能之间的时间间隔。

- 对照原生量谱确认技力和兽力变化。
- 确认大招实际资源消耗和 ActionManager 状态。
- 确认当前兽笛字段在召唤、切换和消失时的值。
- 采集协作量谱状态和 7 秒协作窗口。
- 确认生息/死灭中心状态字段。
- 验证自身捕获与他人捕获状态的 SourceId。
- 验证目标切换、捕获失败、目标死亡和召唤兽消失。

## 安全边界

以下任一条件不满足时，不得自动释放高级技能：

- 量谱读取失败。
- 当前魔兽未知。
- 属性未知。
- ActionId 无效。
- 目标无效。
- 资源门槛未知。
- 协作窗口未知。
- ActionManager 拒绝使用。
