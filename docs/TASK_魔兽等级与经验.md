# 魔兽等级与经验读取任务

## 目标

从游戏 UI 或客户端内存中定位每只已捕获魔兽的养成数据，并在插件魔兽图鉴中显示：

- 当前等级
- 当前经验值
- 升到下一级所需经验值或经验进度

现有图鉴“等级”字段是捕获地点的怪物等级，不是宝宝养成等级，两者必须分开显示和命名。

## 当前进度

第一阶段只读采集工具已实现：

- DEBUG → 项目资料 → “魔兽等级经验结构”
- DEBUG → 项目资料 → “斗兽结算等级经验”

探针读取：

- 当前可见的 `XBMMonsterNotebook` Addon
- 当前页编号
- 当前页 25 项、每项 8 个 `AtkValue` 的类型与原始值
- `AgentId 500` 前 `0x400` 字节的 4 字节候选整数

探针不打开窗口、不翻页、不触发回调、不写入内存。

斗兽塔每轮结束后的 `XBMResult` 结算页会直接显示参战宝宝的结算后等级与经验。正式功能优先在结算页出现时自动读取并更新参战宝宝缓存，因此日常升级不要求手动打开魔兽编队。图鉴或底层常驻结构用于首次全量同步和补齐未参战宝宝。

已通过图鉴 2 松鼠种从 4 级 `61/100` 升至 6 级 `9/100` 的结算确认字段：图标 `73..82`、结算前经验 `89..98`、结算后经验 `105..114`、结算前等级 `121..130`、结算后等级 `137..146`。结算页自动同步、按角色持久化以及图鉴“兽级/经验”显示已经实现。

NPC 原生图鉴的选中详情也已确认：`Value[229]` 为显示编号、`Value[231]` 为图标、`Value[258]` 为兽级、`Value[261]` 为当前经验、`Value[262]` 为经验上限。`Value[227]` 会在切换时滞后，不能作为当前编号。插件以显示编号和图标相互校验，在用户浏览宝宝时自动补充单只记录，不要求打开魔兽编队。

## 采集步骤

1. 打开游戏原生魔兽图鉴并停留在包含目标宝宝的页面。
2. 在插件 DEBUG 中读取“魔兽等级经验结构”，保存第一次结果。
3. 记录目标宝宝的图鉴编号、游戏内当前等级和当前经验。
4. 让该宝宝获得一次可明确确认的经验，尽量不要同时改变其他宝宝的数据。
5. 再次打开同一图鉴页并读取“魔兽等级经验结构”。
6. 对比两份结果，寻找只随该宝宝经验变化的字段或 Agent 偏移。
7. 在宝宝升级前后重复一次，确认等级字段与经验归零或结转方式。
8. 对第一页和第二页各验证至少一只宝宝，确认 50 项数据的索引规则。

结算页采集：

1. 一轮斗兽结束后停留在显示“获得经验值”的页面。
2. 运行“斗兽结算等级经验”。
3. 记录每个参战宝宝的图鉴编号、结算后等级和经验文本。
4. 对照探针的 `XBMResult.AtkValues` 和 Agent 505 候选字段。
5. 至少采集一次普通加经验和一次升级结算，确认经验结转规则。

## 安全边界

- 未确认字段前不写入正式配置或图鉴数据。
- 不通过猜测偏移显示等级或经验。
- 所有客户端访问只读，不修改游戏内存。
- 校验 Agent、Addon、字段数量、页码和数据范围，异常时显示未知而不是旧值。
- 游戏版本更新后重新验证偏移和结构。

## 完成标准

- 50 只魔兽能够按图鉴编号稳定映射等级和经验。
- 未捕获魔兽、满级魔兽和跨页数据均能正确处理。
- 图鉴关闭后仍能通过安全缓存显示最近一次有效数据，重新登录不会串角色。
- 等级或经验读取失败时不影响现有图鉴同步和捕获进度。
